# Detour — Route Generator V2

> 狀態：ACTIVE / 三 Mood 共用一般目的地路線
> 日期：2026-09-17

## 核心原則

**允許整趟走向不日常，但不允許局部看起來像導航犯蠢。**

隨便走、色色的、吃東西都用「正常步行時間適合的目的地」控制旅程長度；不為了湊時間替同一個終點硬塞繞路。

使用者選擇的時間代表完整體驗時間，包含步行、尋找、拍照、路口停等與抵達。路線評分以整趟估計時間接近所選時間為目標，容許約 ±10% 誤差。

## 一般目的地 Journey

1. Scene Engine 先依時間與 Mood 產生候選目的地。
2. Routing Engine 對少量 shortlist 計算正常步行路線。
3. 淘汰超時、重複近期街段、整體過度曲折或局部明顯繞路的候選。
4. 由目的地品質與 Route Quality 共同決定 Journey。

時間不足時應換更遠的目的地，不應把較近目的地的人為路線拉長。

## 局部捷徑後悔

Routing Engine 會檢查約 120–460 公尺的局部視窗，計算該段實走長度與同一對端點直線距離的比值。

- preferred：最多約 1.38
- fallback：最多約 1.58
- emergency：最多約 1.82

這是保守的幾何警示，不宣稱知道所有道路實際通行狀態。它的目的，是避免「走完兩個直角邊，才發現旁邊有一條明顯斜邊」的失落感。

## Night Route Profile

夜間由所在地太陽高度自動觸發，且「優先走明亮大路」預設開啟，使用者可在設定關閉。夜間 Scene 仍先遵守 Scene Engine 的 `lit` 與類型限制；Routing Engine 另外向 OSRM 要求替代路線，並在最多約 10% 距離、12% 時間增加內，偏好：

- 有名稱的道路比例較高
- 轉折較少、較容易辨識
- 局部繞路較少

OSM 的照明資料並不完整，因此這些訊號代表「較容易辨識、較像有人活動的主要路線」，不是安全保證。沒有足夠資料時仍保留正常最短步行路線，不會為了虛假的安全分數大幅繞遠。

## 已移除：慢慢走

固定目的地的延長路線會產生違反直覺的刻意繞路，因此「慢慢走」以及地址 geocode、弧線 waypoint 與延長路線挑選邏輯已從正式產品移除。

若未來測試「繞一圈」，它應是回到起點的獨立 Route Mode，不應塞回三個 Mood 的目的地流程。
