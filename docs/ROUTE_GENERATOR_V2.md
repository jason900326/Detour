# Detour — Route Generator V2

> 狀態：ACTIVE / 一般路線與慢慢走第一版已實作
> 日期：2026-09-16

## 核心原則

**允許整趟走向不日常，但不允許局部看起來像導航犯蠢。**

隨便走、色色的、吃東西用「正常步行時間適合的目的地」控制旅程長度；不為湊時間替同一個終點硬塞繞路。只有慢慢走可以在目的地固定時主動延長路線。

使用者選擇的 15 / 30 / 45 / 60 / 90 分鐘代表完整體驗時間，包含步行、尋找、拍照、路口停等與抵達。路線評分以整趟估計時間接近所選時間為目標，容許約 ±10% 誤差。

## 一般目的地 Journey

適用於隨便走、色色的、吃東西：

1. Scene Engine 先依時間與 Mood 產生候選目的地。
2. Routing Engine 對少量 shortlist 計算正常步行路線。
3. 淘汰超時、重複近期街段、整體過度曲折或局部明顯繞路的候選。
4. 由目的地品質與 Route Quality 共同決定 Journey。

時間不足時應換更遠的目的地，不應把較近目的地的人為路線拉長。

## 局部捷徑後悔

Routing Engine 會檢查約 120–460 公尺的局部視窗，計算該段實走長度與同一對端點直線距離的比值。

- preferred：最多約 1.38
- fallback：最多約 1.58
- emergency：最多約 1.82

這是保守的幾何警示，不宣稱知道所有道路實際通行狀態。它的目的，是避免「走完兩個直角邊，才發現旁邊有一條明顯斜邊」的失落感。

## Night Route Profile

夜間由所在地太陽高度自動觸發，且「優先走明亮大路」預設開啟，使用者可在設定關閉。夜間 Scene 仍先遵守 Scene Engine 的 `lit` 與類型限制；Routing Engine 另外向 OSRM 要求替代路線，並在最多約 10% 距離、12% 時間增加內，偏好：

- 有名稱的道路比例較高
- 轉折較少、較容易辨識
- 局部繞路較少

OSM 的照明資料並不完整，因此這些訊號代表「較容易辨識、較像有人活動的主要路線」，不是安全保證。沒有足夠資料時仍保留正常最短步行路線，不會為了虛假的安全分數大幅繞遠。

## 慢慢走

慢慢走使用獨立 Route Generator：

- 使用者指定目的地。
- 先計算最短路線，確認時間預算足夠。
- 只在可形成自然弧線且不重複街段時延長。
- 禁止 U-turn、同一路段來回與目的地附近硬繞圈。
- 無法自然填滿時間時，允許稍早抵達。

目前消費者流程會先要求使用者輸入台灣地址或地標，再由系統 geocode 成目的地。Route Generator 先取得最短步行路線，接著在直線方向的兩側各建立一組平滑弧線候選，交給 OSRM 吸附到實際道路；中繼點若離可步行道路超過 100 公尺便淘汰。

延長候選必須同時通過：

- 不走回 150 公尺前已經走過的街段。
- 不出現局部明顯三角形繞路。
- 不超過完整時間預算約 10%。
- 夜間不能大量依賴無名小路。
- 不高度重複近期旅程街段。

兩側都無法形成自然弧線時，直接採用最短路線並提早抵達；不使用隨機座標硬湊時間。
